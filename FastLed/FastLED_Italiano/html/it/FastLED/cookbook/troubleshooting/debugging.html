Monitoraggio Seriale¶

Utilizzare l’uscita seriale per monitorare lo stato e le prestazioni del sistema LED.

Configurazione di Base della Seriale¶

void setup() {
    Serial.begin(115200);
    while (!Serial) { }  // Wait for serial (Leonardo/Micro only)

    Serial.println("FastLED Starting...");

    FastLED.addLeds<WS2812B, LED_PIN, GRB>(leds, NUM_LEDS);
    Serial.println("LEDs initialized");
}

void loop() {
    // Print diagnostic info
    EVERY_N_SECONDS(5) {
        Serial.print("FPS: ");
        Serial.println(FastLED.getFPS());
    }
}

Suggerimenti:

  • Utilizzare 115200 baud per un output più veloce

  • Rimuovere while (!Serial) per le schede non USB (si bloccherà)

  • Leonardo/Micro richiedono wait; Uno/Mega no

Pattern di Test per Verificare la Configurazione¶

Utilizzare questo pattern di test completo per verificare l’hardware e il cablaggio:

void testPattern() {
    // Test RED
    fill_solid(leds, NUM_LEDS, CRGB::Red);
    FastLED.show();
    delay(1000);

    // Test GREEN
    fill_solid(leds, NUM_LEDS, CRGB::Green);
    FastLED.show();
    delay(1000);

    // Test BLUE
    fill_solid(leds, NUM_LEDS, CRGB::Blue);
    FastLED.show();
    delay(1000);

    // Test individual LEDs
    FastLED.clear();
    for (int i = 0; i < NUM_LEDS; i++) {
        leds[i] = CRGB::White;
        FastLED.show();
        Serial.print("LED ");
        Serial.println(i);
        delay(100);
    }
}

Cosa testa:

  • Canali colore funzionanti correttamente

  • Tutti i LED funzionanti

  • Segnale dati che raggiunge tutti i LED

  • Identifica quale LED è guasto (se c’è)

Utilizzo: Richiamare testPattern() da setup() o premendo un pulsante

Controllo dell’Utilizzo della Memoria¶

Monitorare l’utilizzo della RAM per prevenire problemi di memoria insufficiente, soprattutto sulle schede AVR.

void setup() {
    Serial.begin(115200);

    // Calculate memory usage
    int ledMemory = NUM_LEDS * sizeof(CRGB);
    Serial.print("LED array uses: ");
    Serial.print(ledMemory);
    Serial.println(" bytes");

    // Check available RAM (AVR only)
    #ifdef __AVR__
    extern int __heap_start, *__brkval;
    int freeMemory;
    if ((int)__brkval == 0) {
        freeMemory = ((int)&freeMemory) - ((int)&__heap_start);
    } else {
        freeMemory = ((int)&freeMemory) - ((int)__brkval);
    }
    Serial.print("Free RAM: ");
    Serial.print(freeMemory);
    Serial.println(" bytes");
    #endif
}

Linee guida sulla memoria:

  • Ogni LED = 3 byte (RGB)

  • Arduino Uno: 2 KB di RAM totale (max ~500-600 LED dopo l’overhead)

  • Arduino Mega: 8 KB di RAM totale (max ~2000 LED dopo l’overhead)

  • ESP32/ESP8266: molta più RAM disponibile

Debug dei problemi di colore¶

Verificare che l’ordine e i valori dei colori siano corretti:

void debugColors() {
    // Test if colors are correct
    leds[0] = CRGB(255, 0, 0);    // Should be RED
    leds[1] = CRGB(0, 255, 0);    // Should be GREEN
    leds[2] = CRGB(0, 0, 255);    // Should be BLUE
    FastLED.show();

    // If colors are wrong, try different COLOR_ORDER:
    // RGB, RBG, GRB, GBR, BRG, BGR
}

Debug avanzato dei colori:

void printColorValues() {
    for (int i = 0; i < min(10, NUM_LEDS); i++) {
        Serial.print("LED ");
        Serial.print(i);
        Serial.print(": R=");
        Serial.print(leds[i].r);
        Serial.print(" G=");
        Serial.print(leds[i].g);
        Serial.print(" B=");
        Serial.println(leds[i].b);
    }
}

Monitoraggio del Frame Rate¶

Monitorare le prestazioni e identificare i rallentamenti:

void loop() {
    updatePattern();
    FastLED.show();

    EVERY_N_SECONDS(1) {
        uint16_t fps = FastLED.getFPS();
        Serial.print("FPS: ");
        Serial.println(fps);

        if (fps < 30) {
            Serial.println("WARNING: Low frame rate!");
        }
    }
}

Interpretazione dei risultati:

  • Oltre 60 FPS: Prestazioni eccellenti

  • 30-60 FPS: Buono per la maggior parte delle applicazioni

  • <30 FPS: Potrebbe apparire discontinuo, ottimizzare il codice

  • <10 FPS: Probabile problema di prestazioni

Cause comuni di FPS bassi:

  • Troppi LED per la velocità del processore

  • Calcoli complessi in loop

  • Istruzioni Serial.print() nel percorso attivo (rimuovere dopo il debug)

  • Ritardi bloccanti

Verificare la Corruzione dei Dati¶

Verificare che l’array di dati dei LED non sia danneggiato:

void validateLEDData() {
    bool hasError = false;

    for (int i = 0; i < NUM_LEDS; i++) {
        // Check for impossible values
        if (leds[i].r > 255 || leds[i].g > 255 || leds[i].b > 255) {
            Serial.print("ERROR at LED ");
            Serial.println(i);
            hasError = true;
        }
    }

    if (!hasError) {
        Serial.println("LED data OK");
    }
}

Quando utilizzare:

  • Colori strani che compaiono

  • Comportamento casuale dei LED

  • Dopo operazioni complesse con i puntatori

  • Sospetto buffer overrun

Test Hardware Completo¶

Test diagnostico completo per la verifica dell’hardware:

// Comprehensive hardware test
void hardwareTest() {
    Serial.begin(115200);
    delay(1000);

    Serial.println("=== FastLED Hardware Test ===");

    // Test 1: Single LED
    Serial.println("Test 1: First LED RED");
    FastLED.clear();
    leds[0] = CRGB::Red;
    FastLED.show();
    delay(2000);

    // Test 2: All RED
    Serial.println("Test 2: All LEDs RED");
    fill_solid(leds, NUM_LEDS, CRGB::Red);
    FastLED.show();
    delay(2000);

    // Test 3: Color test
    Serial.println("Test 3: Color sequence");
    CRGB colors[] = {CRGB::Red, CRGB::Green, CRGB::Blue, CRGB::White};
    for (int c = 0; c < 4; c++) {
        fill_solid(leds, NUM_LEDS, colors[c]);
        FastLED.show();
        delay(1000);
    }

    // Test 4: Individual LEDs
    Serial.println("Test 4: Individual LED scan");
    FastLED.clear();
    for (int i = 0; i < NUM_LEDS; i++) {
        leds[i] = CRGB::White;
        FastLED.show();
        delay(50);
        leds[i] = CRGB::Black;
    }

    Serial.println("=== Test Complete ===");
}

Per l’Utilizzo: Chiamare hardwareTest() da setup() o creare uno sketch di test

Cosa testa:

  1. Funzionalità del primo LED (punto di guasto più comune)

  2. Tutti i LED possono visualizzare lo stesso colore

  3. Canali colore funzionanti (R, G, B e combinati)

  4. Ogni singolo LED funzionante e indirizzabile

Debug dei Problemi di Temporizzazione¶

Verificare la presenza di problemi di temporizzazione con animazioni:

unsigned long lastFrameTime = 0;
unsigned long frameCount = 0;

void loop() {
    unsigned long now = millis();
    unsigned long frameTime = now - lastFrameTime;
    lastFrameTime = now;

    EVERY_N_SECONDS(5) {
        Serial.print("Average frame time: ");
        Serial.print(frameTime);
        Serial.println("ms");

        Serial.print("Frames in 5 sec: ");
        Serial.println(frameCount);
        frameCount = 0;
    }

    updateLEDs();
    FastLED.show();
    frameCount++;
}

Strategie di Debug¶

Test di Isolamento¶

Testare i componenti singolarmente:

  1. Testare solo l’alimentatore (tensione, capacità di corrente)

  2. Testare solo il microcontrollore (uscita seriale, semplice lampeggìo del LED)

  3. Testare la striscia LED con un controller funzionante

  4. Combinare i componenti uno alla volta

Ricerca Binaria per LED Difettosi¶

Se i LED funzionano fino a un certo punto:

void findBadLED() {
    int testPoint = NUM_LEDS / 2;

    fill_solid(leds, testPoint, CRGB::Red);
    fill_solid(&leds[testPoint], NUM_LEDS - testPoint, CRGB::Green);
    FastLED.show();

    // Adjust testPoint up or down based on which lights up
    // Repeat until you find the exact failing LED
}

Sketch Minimo di Test¶

Creare lo sketch più semplice possibile per isolare i problemi:

#include <FastLED.h>

#define LED_PIN 5
#define NUM_LEDS 10  // Start with just 10

CRGB leds[NUM_LEDS];

void setup() {
    FastLED.addLeds<WS2812B, LED_PIN, GRB>(leds, NUM_LEDS);
    fill_solid(leds, NUM_LEDS, CRGB::Red);
    FastLED.show();
}

void loop() {
    // Empty - just show red
}
