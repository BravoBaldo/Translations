  • Guida Introduttiva - Controllo LED di base e configurazione FastLED

  • Concetti Fondamentali - In particolare considerazioni su tempi e memoria

  • Pattern di Base - Fondamenti della programmazione dei pattern

  • Tecniche Intermedie - Pattern avanzati che traggono vantaggio dall’ottimizzazione

Si imparerà:

  1. Come identificare ed eliminare colli di bottiglia nelle prestazioni nel codice LED

  2. Tecniche per ottimizzare i calcoli (matematica intera, precalcolo, bit shift)

  3. Strategie di ottimizzazione della memoria per microcontrollori con vincoli

  4. Gestione del frame rate e controllo del consumo energetico

  5. Suggerimenti di ottimizzazione e tecniche di profilazione specifiche per piattaforma

Suggerimenti e tecniche per creare animazioni LED fluide ed efficienti. L’ottimizzazione del codice garantisce frame rate elevati ed effetti reattivi.

Ridurre i Calcoli in Loop¶

Evitare di ricalcolare costanti e operazioni costose a ogni frame.

Svantaggio: Ricalcolare ogni frame¶

void slowEffect() {
    for (int i = 0; i < NUM_LEDS; i++) {
        float angle = (i * 360.0) / NUM_LEDS;  // Expensive floating point math!
        float radians = angle * PI / 180.0;
        // ... more calculations
    }
}

Buono: Precalcolare una Volta¶

uint8_t ledAngles[NUM_LEDS];

void setup() {
    // Calculate once at startup
    for (int i = 0; i < NUM_LEDS; i++) {
        ledAngles[i] = (i * 255) / NUM_LEDS;
    }

    FastLED.addLeds<WS2812B, DATA_PIN, GRB>(leds, NUM_LEDS);
}

void fastEffect() {
    for (int i = 0; i < NUM_LEDS; i++) {
        // Use precalculated value
        uint8_t brightness = sin8(ledAngles[i] + millis() / 10);
        leds[i] = CHSV(160, 255, brightness);
    }
}

Usare Calcoli Interi¶

Le operazioni in virgola mobile sono lente sui microcontrollori. Usare calcoli interi e spostamenti di bit quando possibile.

Divisione in Virgola Mobile (Lenta)¶

float result = (value * 3.14159) / 2.0;

Operazioni Intere (Veloci)¶

// Bit shift for division by powers of 2
uint8_t result = (value * 3) >> 1;  // Divide by 2 using bit shift

// Use FastLED's scale8 for scaling
uint8_t scaled = scale8(value, 128);  // Multiply by 128/255

// Integer approximations
uint8_t approxPi = (value * 157) >> 5;  // Approximate × π (157/50 ≈ π)

Limitare il Frame Rate¶

Non aggiornare i LED più velocemente del necessario. La maggior parte degli effetti risulta fluida a 30-60 FPS.

Semplice Limitazione della Frequenza¶

void loop() {
    EVERY_N_MILLISECONDS(20) {  // Max 50 FPS
        updateLEDs();
        FastLED.show();
    }
    // Other non-blocking tasks can run here
}

Controllo Manuale della Temporizzazione¶

const uint32_t FRAME_TIME = 20;  // 50 FPS
uint32_t lastFrame = 0;

void loop() {
    uint32_t now = millis();

    if (now - lastFrame >= FRAME_TIME) {
        lastFrame = now;
        updateLEDs();
        FastLED.show();
    }

    // Other tasks
}

Frame Rate Adattativo¶

void loop() {
    updateLEDs();
    FastLED.show();

    // Monitor and adjust
    EVERY_N_SECONDS(5) {
        uint16_t fps = FastLED.getFPS();
        if (fps < 30) {
            Serial.println("WARNING: Low frame rate detected!");
        }
    }
}

Gestione Energetica¶

Limitare il consumo energetico per rimanere entro la capacità dell’alimentatore.

void setup() {
    FastLED.addLeds<WS2812B, DATA_PIN, GRB>(leds, NUM_LEDS);

    // Limit total power draw
    FastLED.setMaxPowerInVoltsAndMilliamps(5, 2000);  // 5V, 2A max
}

Questo ridimensiona automaticamente la luminosità per evitare di superare il budget energetico.

Limitazione Manuale della Luminosità¶

void setup() {
    FastLED.setBrightness(50);  // Global brightness limit (0-255)
}

// Or per-effect:
void conservativeBrightness() {
    for (int i = 0; i < NUM_LEDS; i++) {
        leds[i] = CHSV(hue, 255, 128);  // Max 50% brightness
    }
}

Operazioni Efficienti sugli Array¶

Utilizzare le funzioni ottimizzate di FastLED invece dei loop manuali.

Lento: Assegnazioni Individuali¶

for (int i = 0; i < NUM_LEDS; i++) {
    leds[i] = CRGB::Black;
}

Veloce: Funzioni FastLED¶

fill_solid(leds, NUM_LEDS, CRGB::Black);
// Or even faster:
FastLED.clear();

Altre Funzioni Efficienti¶

// Fill with rainbow
fill_rainbow(leds, NUM_LEDS, startHue, deltaHue);

// Fade all LEDs
fadeToBlackBy(leds, NUM_LEDS, fadeAmount);

// Blur for smoothing
blur1d(leds, NUM_LEDS, blurAmount);

Dithering Temporale¶

Il dithering riduce le bande visibili nei gradienti di colore, ma riduce le prestazioni.

void setup() {
    FastLED.addLeds<WS2812B, DATA_PIN, GRB>(leds, NUM_LEDS);

    // Balance quality vs speed
    FastLED.setDither(BINARY_DITHER);  // Better quality (default)
    // FastLED.setDither(DISABLE_DITHER);  // Faster, slight quality loss
}

Per la maggior parte degli effetti, va bene BINARY_DITHER. Disattivarlo solo se c’è bisogno del massimo frame rate.

Ottimizzazione della Memoria¶

Ridurre il Numero di LED¶

Ogni LED utilizza 3 byte di RAM:

  • 100 LED = 300 byte

  • 500 LED = 1.500 byte

  • 1000 LED = 3.000 byte

Su dispositivi con limiti di memoria (Arduino Uno: 2 KB di RAM), considerare:

  • Utilizzare meno LED

  • Suddividere la RAM su più controller

  • Aggiornare a un dispositivo con più RAM (ESP32, Teensy)

Evitare l’Allocazione Dinamica¶

// Bad: Dynamic allocation in loop
void inefficient() {
    CRGB* tempBuffer = new CRGB[NUM_LEDS];  // Slow, fragments memory
    // ...
    delete[] tempBuffer;
}

// Good: Static allocation
CRGB tempBuffer[NUM_LEDS];

void efficient() {
    // Use static buffer
}

Utilizzare tipi di dati più piccoli¶

// If you only need 0-255, use uint8_t
uint8_t brightness = 128;

// Not:
int brightness = 128;  // Uses 2 bytes instead of 1

Ottimizzazioni Specifiche per Pattern¶

Ottimizzare le funzioni di rumore¶

// Slower: Recalculate noise for every LED every frame
void slowNoise() {
    for (int i = 0; i < NUM_LEDS; i++) {
        uint8_t noise = inoise8(i * 100, i * 100, millis());
        leds[i] = CHSV(noise, 255, 255);
    }
}

// Faster: Use simpler parameters
void fastNoise() {
    uint16_t time = millis() / 10;
    for (int i = 0; i < NUM_LEDS; i++) {
        uint8_t noise = inoise8(i * 50, time);  // Fewer calculations
        leds[i] = CHSV(noise, 255, 255);
    }
}

Ottimizzare le Ricerche nella Palette¶

// Precalculate palette index offsets
uint8_t paletteOffsets[NUM_LEDS];

void setup() {
    for (int i = 0; i < NUM_LEDS; i++) {
        paletteOffsets[i] = (i * 256) / NUM_LEDS;
    }
}

void paletteEffect() {
    static uint8_t baseIndex = 0;

    for (int i = 0; i < NUM_LEDS; i++) {
        uint8_t index = baseIndex + paletteOffsets[i];
        leds[i] = ColorFromPalette(palette, index, 255, LINEARBLEND);
    }

    baseIndex++;
}

Suggerimenti Specifici per Piattaforma¶

Arduino Uno/Nano (ATmega328)¶

  • RAM molto limitata (2 KB)

  • CPU lenta (16 MHz)

  • Mantenere il numero di LED al di sotto di 500

  • Evitare Matematica in virgola mobile

  • Utilizzare PROGMEM per dati costanti

ESP32¶

  • Ampia RAM (520 KB)

  • CPU veloce (240 MHz)

  • Utilizzare periferiche RMT per risultati ottimali

  • Può gestire facilmente oltre 1000 LED

  • Disattivare il Wi-Fi durante gli aggiornamenti dei LED per un output più fluido

ESP8266¶

  • RAM limitata (80 KB disponibili)

  • CPU moderata (80/160 MHz)

  • Mantenere un numero ragionevole di LED (500-1000)

  • Il Wi-Fi può causare problemi ai LED

Teensy 4.x¶

  • Prestazioni eccellenti

  • CPU molto veloce (600 MHz)

  • Può pilotare facilmente molti LED

  • Capacità di uscita parallela

Profiling e Debug¶

Misurare il frame rate¶

void loop() {
    updatePattern();
    FastLED.show();

    EVERY_N_SECONDS(1) {
        uint16_t fps = FastLED.getFPS();
        Serial.print("FPS: ");
        Serial.println(fps);

        if (fps < 30) {
            Serial.println("WARNING: Low frame rate!");
        }
    }
}

void profileFunction() {

    // Function to profile
    updateComplexEffect();

    uint32_t duration = micros() - startTime;
    Serial.print("Effect took: ");
    Serial.print(duration);
    Serial.println(" microseconds");

Identificare i colli di bottiglia¶

void findBottleneck() {
    uint32_t t1 = micros();
    part1();
    uint32_t t2 = micros();
    part2();
    uint32_t t3 = micros();
    part3();
    uint32_t t4 = micros();

    Serial.print("Part 1: "); Serial.println(t2 - t1);
    Serial.print("Part 2: "); Serial.println(t3 - t2);
    Serial.print("Part 3: "); Serial.println(t4 - t3);
}

Riepilogo delle Best Practice¶

  1. Precalcolare le costanti - Non ricalcolare gli stessi valori ad ogni frame

  2. Utilizzare calcoli interi - Evitare operazioni in virgola mobile su microcontrollori

  3. Limitare il frame rate - 30-60 FPS sono solitamente sufficienti

  4. Utilizzare le funzioni FastLED - Sono ottimizzate per le prestazioni

  5. Gestirei l’alimentazione - Utilizzare setMaxPowerInVoltsAndMilliamps()

  6. Profilare il codice - Misurare per individuare i colli di bottiglia effettivi

  7. Scegliere l’hardware appropriato - Adattare le proprie esigenze alle capacità della piattaforma

  8. Test incrementali - Aggiungere complessità gradualmente e testare le prestazioni

Insidie ​​Comuni alle Prestazioni¶

Insidia 1: Troppe stampe seriali¶

// BAD: Serial in tight loop
for (int i = 0; i < NUM_LEDS; i++) {
    Serial.println(i);  // Very slow!
    leds[i] = color;
}

// GOOD: Print occasionally
EVERY_N_SECONDS(1) {
    Serial.println("Status: OK");
}

Insidia 2: Ritardi bloccanti¶

// BAD: Blocking delay
void loop() {
    updateLEDs();
    FastLED.show();
    delay(1000);  // Nothing can happen during delay
}

// GOOD: Non-blocking timing
EVERY_N_MILLISECONDS(1000) {
    updateLEDs();
}

Insidia 3: Aggiornamenti Full Strip non necessari¶

// If only a few LEDs change, don't recalculate all
// Instead, fade existing and add new:
fadeToBlackBy(leds, NUM_LEDS, 10);
leds[newPos] = CRGB::White;  // Only set changed LED

Passaggi successivi:

  • Profilare gli effetti per individuare i colli di bottiglia effettivi

  • Sperimentare diversi frame rate per l’installazione

  • Testa sulla propria piattaforma hardware

  • Bilanciare qualità e prestazioni in base alle esigenze specifiche
