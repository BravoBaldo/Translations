Tempistiche e Frame Rate¶

Controllare la velocità e la temporizzazione dell’animazione in FastLED.

Ritardo Semplice¶

Il metodo di temporizzazione più semplice che utilizza delay():

void loop() {
    updateLEDs();
    FastLED.show();
    delay(20);  // ~50 FPS (20ms between frames)
}

Pro: Semplice, facile da capire Contro: Blocca l’esecuzione del codice: non è possibile eseguire altro codice durante il ritardo

Calcolo del Frame Rate¶

Frame rate (FPS) = 1000ms / delay_time

Examples:
- delay(20)  = 50 FPS
- delay(10)  = 100 FPS
- delay(50)  = 20 FPS
- delay(100) = 10 FPS

La Macro EVERY_N_MILLISECONDS¶

Temporizzazione non bloccante tramite la macro integrata di FastLED:

void loop() {
    EVERY_N_MILLISECONDS(20) {  // 50 FPS
        updateLEDs();
        FastLED.show();
    }

    // Other code can run here
    checkButtons();
    readSensors();
}

Pro: Non bloccante, è possibile eseguire altro codice Contro: Intervallo fisso, meno preciso della temporizzazione personalizzata

Macro EVERY_N_SECONDS¶

Per aggiornamenti più lenti:

void loop() {
    EVERY_N_SECONDS(1) {
        Serial.println("One second elapsed");
    }

    EVERY_N_MILLISECONDS(20) {
        updateLEDs();
        FastLED.show();
    }
}

Temporizzazione Non Bloccante Personalizzata¶

Controllo completo tramite millis():

uint32_t lastUpdate = 0;
const uint32_t updateInterval = 20;  // 20ms = 50 FPS

void loop() {
    uint32_t now = millis();

    if (now - lastUpdate >= updateInterval) {
        lastUpdate = now;

        updateLEDs();
        FastLED.show();
    }

    // Other code runs every loop
    checkButtons();
}

Pro: Controllo preciso e non bloccante Contro: Più codice da gestire

Intervalli di Temporizzazione Multipli¶

Eseguire effetti diversi a velocità diverse:

uint32_t lastLEDUpdate = 0;
uint32_t lastSerialUpdate = 0;

const uint32_t LED_INTERVAL = 20;     // 50 FPS
const uint32_t SERIAL_INTERVAL = 1000; // 1 Hz

void loop() {
    uint32_t now = millis();

    // Update LEDs at 50 FPS
    if (now - lastLEDUpdate >= LED_INTERVAL) {
        lastLEDUpdate = now;
        updateLEDs();
        FastLED.show();
    }

    // Print status at 1 Hz
    if (now - lastSerialUpdate >= SERIAL_INTERVAL) {
        lastSerialUpdate = now;
        Serial.println("Status update");
    }
}

FastLED.delay()¶

FastLED offre una propria funzione di ritardo con dithering integrato:

void loop() {
    updateLEDs();
    FastLED.show();
    FastLED.delay(20);  // Like delay() but maintains dithering
}

Usare FastLED.delay() invece di delay() per una migliore resa cromatica.

Misurazione del Frame Rate¶

Monitoraggio degli FPS effettivi:

void loop() {
    updateLEDs();
    FastLED.show();

    EVERY_N_SECONDS(1) {
        uint16_t fps = FastLED.getFPS();
        Serial.print("FPS: ");
        Serial.println(fps);
    }

    delay(20);
}

Effetti a Velocità Variabile¶

Rendere configurabile la velocità dell’animazione:

uint8_t animationSpeed = 10;  // Adjustable speed

void loop() {
    EVERY_N_MILLISECONDS(20) {
        static uint8_t hue = 0;

        fill_rainbow(leds, NUM_LEDS, hue, 7);
        FastLED.show();

        hue += animationSpeed;  // Speed controls how fast hue changes
    }
}

Animazione Basata sul Tempo¶

Usare millis() irettamente per effetti fluidi:

void loop() {
    uint32_t now = millis();

    for (int i = 0; i < NUM_LEDS; i++) {
        // Create time-based wave
        uint8_t brightness = sin8(now / 10 + i * 20);
        leds[i] = CHSV(160, 255, brightness);
    }

    FastLED.show();
}

Effetti sincronizzati al ritmo¶

Usare le funzioni di battuta di FastLED:

void loop() {
    // Sawtooth wave (0-255 repeating)
    uint8_t beat = beat8(60);  // 60 BPM

    // Sine wave (0-255 oscillating)
    uint8_t sineBeat = beatsin8(60, 0, 255);

    // Apply to LEDs
    fill_solid(leds, NUM_LEDS, CHSV(beat, 255, 255));
    FastLED.show();
}

Problemi di Temporizzazione¶

Overflow di millis()¶

millis() va in overflow dopo circa 49 giorni. Gestione corretta:

// GOOD: Subtraction handles overflow correctly
uint32_t now = millis();
if (now - lastUpdate >= interval) {
    // This works even after overflow
}

// BAD: Direct comparison fails after overflow
if (millis() >= lastUpdate + interval) {
    // Don't use this pattern
}

Interferenza degli Interrupt¶

Alcune operazioni possono interferire con la temporizzazione dei LED:

void loop() {
    // Disable interrupts during critical LED update
    noInterrupts();
    FastLED.show();
    interrupts();

    // Other code
}

Su ESP32, il WiFi può interferire. Valutare la possibilità di disabilitare il WiFi durante FastLED.show().

Ottimizzazione delle Prestazioni¶

Limita la Frequenza di Aggiornamento¶

Non aggiornare più velocemente del necessario:

// WASTEFUL: 1000+ FPS (updates too fast)
void loop() {
    updateLEDs();
    FastLED.show();  // No delay
}

// BETTER: 50 FPS is plenty
void loop() {
    EVERY_N_MILLISECONDS(20) {
        updateLEDs();
        FastLED.show();
    }
}

Separare il Calcolo dal Display¶

void loop() {
    EVERY_N_MILLISECONDS(20) {
        // Only call show() when needed
        FastLED.show();
    }

    // Calculate every loop (faster)
    updateLEDs();
}

Esempi Pratici¶

Dissolvenza Fluida in Entrata/Uscita¶

void fadeInOut() {
    static uint8_t brightness = 0;
    static int8_t direction = 1;

    EVERY_N_MILLISECONDS(10) {
        brightness += direction;

        if (brightness == 0 || brightness == 255) {
            direction = -direction;
        }

        FastLED.setBrightness(brightness);
        fill_solid(leds, NUM_LEDS, CRGB::Purple);
        FastLED.show();
    }
}

Chase a Velocità Controllata¶

uint8_t chaseSpeed = 50;  // ms between steps

void chase() {
    static uint8_t pos = 0;
    static uint32_t lastMove = 0;

    uint32_t now = millis();
    if (now - lastMove >= chaseSpeed) {
        lastMove = now;

        FastLED.clear();
        leds[pos] = CRGB::Red;
        FastLED.show();

        pos = (pos + 1) % NUM_LEDS;
    }
}

Effetto Multi-Velocità¶

void multiSpeed() {
    static uint8_t hue1 = 0;
    static uint8_t hue2 = 128;

    // Fast effect (every 10ms)
    EVERY_N_MILLISECONDS(10) {
        leds[0] = CHSV(hue1, 255, 255);
        hue1 += 2;
    }

    // Slow effect (every 50ms)
    EVERY_N_MILLISECONDS(50) {
        leds[NUM_LEDS - 1] = CHSV(hue2, 255, 255);
        hue2++;
    }

    // Update display at fixed rate
    EVERY_N_MILLISECONDS(20) {
        FastLED.show();
    }
}

Best Practice¶

  1. Utilizzare tempi non bloccanti per un codice reattivo

  2. Puntare a 30-60 FPS - valori più alti di solito non sono necessari

  3. Separare il calcolo dal display quando possibile

  4. Usare FastLED.delay() invece di delay() per un dithering migliore

  5. Monitorare gli FPS durante lo sviluppo per individuare problemi di prestazioni
