10 Setting Up the Poky Reference Distro Manually

While the default way to set up the Poky reference distro is to use bitbake-setup, it is also possible to manually set up the environment. This document guides through this setup step-by-step.

Nota

This document will produce a setup similar to what is described in Build Rapida di un'Immagine con lo Yocto Project, which shows how to set up Poky with bitbake-setup.

10.1 Obtaining The Source Repositories

You can obtain the source repositories required to build the Poky reference distro in two ways described below: cloning the repositories with Git, or downloading the released archives.

10.1.1 Use Git to Clone The Layers

Go to the Releases page, and choose a release (such as yocto-6.1_M3), corresponding to either the latest stable release or a Long Term Support release.

Once you complete the setup instructions for your machine (see the Requisiti di Sistema section of the Yocto Project Reference Manual), create a Source Directory: the base directory for your project. Throughout the documentation, we will use bitbake-builds as the name of the Source Directory. Here's how to create it:

$ mkdir bitbake-builds
$ cd bitbake-builds

You need to get a copy of the different layers needed to set up the Poky reference distribution on your build host. Use the following commands:

$ mkdir layers/
$ git clone -b yocto-6.1_M3 https://git.openembedded.org/bitbake ./layers/bitbake
$ git clone -b yocto-6.1_M3 https://git.openembedded.org/openembedded-core ./layers/openembedded-core
$ git clone -b yocto-6.1_M3 https://git.yoctoproject.org/meta-yocto ./layers/meta-yocto

10.1.2 Using the Source Archives

The Yocto Project also provides source archives of its releases, which are available at https://downloads.yoctoproject.org/releases/yocto/. Then, choose the subdirectory containing the release you wish to use, for example yocto-6.1_M3.

You will find there source archives of OpenEmbedded-Core (OE-Core), BitBake, and meta-yocto.

Nota

The recommended method for accessing Yocto Project components is to use Git to clone the upstream repository and work from within the locally cloned repositories.

10.2 Building dell'Immagine

Seguire i passaggi seguenti per compilare l'immagine. Il processo di compilazione (build) crea un'intera distribuzione Linux, inclusa la toolchain, a partire dai sorgenti.

Nota

  • Se si lavora dietro un firewall e l'host di build non è configurato per i proxy, si potrebbero riscontrare problemi con il processo di build durante il recupero del codice sorgente (ad esempio, errori di fetcher o errori di Git).

  • Se non si conoscono le impostazioni del proxy, consulta le risorse della propria infrastruttura di rete locale per ottenere queste informazioni. Un buon punto di partenza potrebbe essere anche controllare le impostazioni del browser web. Infine, si possono trovare maggiori informazioni nella pagina "Working Behind a Network Proxy" nello Yocto Project Wiki.

  1. Initialize the Build Environment: From your current working directory, set up a build environment with the following command:

    $ source ./layers/openembedded-core/oe-init-build-env

    Among other things, the script creates the Build Directory, which is build in this case and is located in the Source Directory. After the script runs, your current working directory is set to the Build Directory. Later, when the build completes, the Build Directory contains all the files created during the build.

  2. Examine Your Local Configuration File: When you set up the build environment, a local configuration file named build/conf/local.conf becomes available in a conf sub-directory of the Build Directory. For this example, the defaults are set to build for a qemux86-64 target, which is suitable for emulation. The package manager used is set to the RPM package manager.

    Suggerimento

    È possibile velocizzare significativamente la compilazione e proteggersi dagli errori del fetcher utilizzando i mirror Cache di Shared State e abilitando Equivalenza degli Hash. Ciò è rilevante solo se la rete e il server utilizzati possono scaricare questi artefatti più velocemente di quanto sarebbe possibile crearli.

    To use such mirrors, run the following command:

    $ bitbake-config-build enable-fragment core/yocto/sstate-mirror-cdn

    Il server di equivalenza hash richiede il modulo Python websockets versione 9.1 o successiva. Debian GNU/Linux 12 (Bookworm) e versioni successive, Fedora, CentOS Stream 9 e versioni successive e Ubuntu 22.04 (LTS) e versioni successive dispongono tutte di un pacchetto sufficientemente recente. Le altre distribuzioni supportate devono ottenere il modulo da una fonte diversa dal proprio feed di pacchetti, ad esempio tramite pip. In alternativa, è possibile installare un tarball di Buildtools seguendo le istruzioni nella sezione Versioni richieste di Git, tar, Python, make e gcc del Manuale di Riferimento di Yocto Project.

  3. Avvio della Build: Continuare col seguente comando per creare un'immagine del sistema operativo per il target, che in questo esempio è core-image-sato:

    $ bitbake core-image-sato

    Per informazioni sull'utilizzo del comando bitbake, consulta la sezione BitBake nel Manuale Introduttivo e Concetti di Yocto Project, oppure consultare The BitBake Command nel Manuale Utente di BitBake.

  4. Simulare l'Immagine con QEMU: Una volta creata questa immagine, si può avviare QEMU, un "Quick EMUlator" incluso nello Yocto Project:

    $ runqemu qemux86-64

    Per ulteriori informazioni sull'esecuzione di QEMU, consultare il capitolo Using the Quick EMUlator (QEMU) nel Manuale di Sviluppo dei Task di Yocto Project.

  5. Uscita da QEMU: Per uscire da QEMU, cliccare sull'icona di spegnimento oppure digitare Ctrl-C nella finestra di trascrizione di QEMU da cui è stato avviato il programma.
