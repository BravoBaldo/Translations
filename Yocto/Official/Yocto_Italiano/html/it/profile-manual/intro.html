1 Manuale di Profilazione e Tracing di Yocto Project

1.1 Introduzione

Yocto Project include una serie di strumenti di tracing [tracciamento] e profilazione: questo manuale ne descrive l'utilizzo di base e mostra, tramite esempi, come impiegarli per analizzare il comportamento di applicazioni e sistemi.

I tool presentati sono, per la maggior parte, completamente aperti e dispongono di una documentazione completa e/o esaustiva che può essere utilizzata per risolvere praticamente qualsiasi problema si possa incontrare in Linux. Ogni sezione che descrive un tool specifico contiene link alla relativa documentazione e al sito web.

Lo scopo di questo manuale è presentare una serie di idiomi di tracing e profilazione comuni e generalmente utili, insieme alla loro applicazione (ove appropriato) a ciascun tool, nel contesto di una metodologia di analisi approfondita di carattere generale, applicabile alla risoluzione di un'ampia gamma di problemi. Per assistenza su utilizzi e problematiche più avanzate, fare riferimento alla documentazione e/o ai siti web forniti per ciascun tool.

La sezione finale di questo manuale è una raccolta di esempi pratici che aggiorneremo costantemente man mano che risolveremo nuovi problemi utilizzando i tool: non esitate a suggerire ulteriori esempi.

1.2 Configurazione Generale

La maggior parte degli strumenti è disponibile solo nelle immagini sdk o nelle immagini create dopo aver aggiunto tools-profile alla variabile EXTRA_IMAGE_FEATURES.

Pertanto, per poter accedere a tutti gli strumenti descritti qui, è possibile creare e avviare un'immagine sdk, ad esempio una delle seguenti:

$ bitbake core-image-sato-sdk
$ bitbake core-image-weston-sdk
$ bitbake core-image-rt-sdk

In alternativa, è possibile aggiungere tools-profile alla riga EXTRA_IMAGE_FEATURES nel file build/conf/local.conf:

EXTRA_IMAGE_FEATURES:append = " tools-profile"

Se si utilizza il metodo tools-profile, non è necessario creare un'immagine sdk: gli strumenti di tracing e profilazione saranno inclusi anche nelle immagini non sdk, ad esempio:

$ bitbake core-image-sato

Nota

Per default, il sistema di compilazione Yocto rimuove i simboli dai binari che impacchetta, il che rende difficile l'utilizzo di alcuni tool.

È possibile evitarlo impostando la variabile INHIBIT_PACKAGE_STRIP su "1" nel file build/conf/local.conf durante la creazione dell'immagine:

INHIBIT_PACKAGE_STRIP = "1"

L'impostazione sopra descritta aumenterà notevolmente le dimensioni dell'immagine.

Se è stata già creata un'immagine senza pacchetti, si possono generare pacchetti di debug (xxx-dbg) che si potranno installare manualmente secondo necessità.

Per generare informazioni di debug per i pacchetti, è possibile aggiungere dbg-pkgs a EXTRA_IMAGE_FEATURES nel file build/conf/local.conf. Ad esempio:

EXTRA_IMAGE_FEATURES:append = " dbg-pkgs"

Inoltre, per generare il tipo corretto di informazioni di debug, è necessario impostare anche PACKAGE_DEBUG_SPLIT_STYLE nel file build/conf/local.conf:

PACKAGE_DEBUG_SPLIT_STYLE = 'debug-file-directory'
