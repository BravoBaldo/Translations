2 Segnalazione di Vulnerabilità

Yocto Project e OpenEmbedded sono progetti open source, basati sulla community, utilizzati in numerosi prodotti. Essi integrano diversi altri progetti open source e devono gestire problematiche e pratiche di sicurezza sia interne (nel codice gestito da entrambi i progetti) che esterne (gestite da altri progetti e organizzazioni).

Questo manuale raccoglie informazioni relative alla sicurezza dell'intero ecosistema. Include informazioni su come segnalare una potenziale vulnerabilità, sul funzionamento del team di sicurezza di YP e su come contribuire al codice correlato. È stato scritto per essere utile sia ai ricercatori di sicurezza che agli sviluppatori YP.

2.1 Come segnalare una potenziale vulnerabilità di sicurezza?

Per segnalare un problema pubblico (ad esempio, uno con un numero CVE rilasciato), segnalarlo utilizzando il Security Bugzilla.

Se si riscontra un problema non ancora rilasciato o se si tratta di un problema urgente, inviare un messaggio security AT yoctoproject DOT org, includendo il maggior numero possibile di dettagli: il layer o il modulo software interessato, la ricetta e la sua versione, ed eventuali esempi di codice, se disponibili. Questa mailing list è monitorata dal team di Yocto Project Security.

Per ogni layer, si possono anche cercare istruzioni specifiche (se presenti) per la segnalazione di potenziali problemi di sicurezza nel file SECURITY.md nella directory principale del repository. Le istruzioni su come e dove inviare una patch sono generalmente disponibili nel file README.md. Se questa è la prima patch per Yocto Project/OpenEmbedded, si dovrebbe consultare la sezione "Preparazione delle Modifiche per l'Invio".

2.1.1 Branch mantenuti con correzioni di sicurezza

Consultare la documentazione Processo di rilascio per i dettagli relativi alle politiche e alla manutenzione dei branch stabili.

La pagina Releases contiene un elenco di tutti i rilasci di Yocto Project, suddivisi in rilasci correnti e precedenti. I rilasci precedenti non sono più attivamente mantenuti con patch di sicurezza, ma le patch ben testate possono ancora essere accettate per la risoluzione di problemi significativi.

2.1.2 Discussioni relative alla sicurezza in Yocto Project

Abbiamo creato due mailing list/email relative alla sicurezza:

  • Public Mailing List: yocto [dash] security [at] yoctoproject[dot] org

    Questa è una mailing list pubblica a cui chiunque può iscriversi. Questa lista è aperta per discutere di problemi/patch di sicurezza pubblici e iniziative relative alla sicurezza. Per ulteriori informazioni, incluse quelle relative all'iscrizione, consultare la pagina informativa della mailing list yocto-security mailing list info page.

    Questa lista richiede l'approvazione di un moderatore per la pubblicazione di nuovi argomenti, al fine di evitare la pubblicazione accidentale di segnalazioni di sicurezza private.

  • Yocto Project Security Team: security [at] yoctoproject [dot] org

    Questo indirizzo email è dedicato alla segnalazione di potenziali vulnerabilità non ancora pubblicate. Le email inviate a questo indirizzo vengono inoltrate ai membri di Yocto Project Security Team.

2.1.3 Cosa fare in caso di vulnerabilità di sicurezza

Se si riscontra una falla di sicurezza: un crash, una fuga di informazioni o qualsiasi altra vulnerabilità che, se sfruttata, possa avere un impatto sulla sicurezza di qualsiasi software open source sviluppato o utilizzato da Yocto Project, si prega di segnalarla al Yocto Project Security Team. Se si preferisce contattare direttamente il progetto upstream, si prega di inviare una copia anche al team di sicurezza di Yocto Project. Se si ritiene che si tratti di informazioni altamente sensibili, segnalare la vulnerabilità in modo sicuro, ad esempio crittografando l'e-mail e inviandola alla lista privata. In questo modo si evita che la vulnerabilità venga divulgata e sfruttata prima che sia stata elaborata una risposta o una soluzione.
