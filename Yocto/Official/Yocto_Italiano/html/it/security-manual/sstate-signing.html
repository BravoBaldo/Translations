6 Firma dello Stato Condiviso

Il sistema di build OpenEmbedded Build System dispone di un meccanismo integrato che consente di risparmiare tempo di esecuzione riutilizzando artefatti precompilati: la cache dello shared state (sstate cache). Questi artefatti sono memorizzati in una directory (SSTATE_DIR) e non sono firmati per default.

Questo documento illustra i passaggi per abilitare la firma dello shared state. Questa funzionalità dipende completamente da GPG, il che significa che gli esempi mostrati in questo documento utilizzeranno il tool da riga di comando gpg.

6.1 Requisiti dell'Host

Poiché GPG non fa parte dei requisiti requisiti host di default, sarà necessario installarlo sull'host.

Ad esempio, le distribuzioni basate su Debian lo forniscono tramite il pacchetto gpg. Installarlo come segue:

$ sudo apt-get install gpg

Verificare che l'installazione sia andata a buon fine controllando la versione di GPG:

$ gpg --version

6.2 Generazione di Una Coppia di Chiavi Pubblica e Privata con GPG

Nota

Questo passaggio è facoltativo se si dispone già di una coppia di chiavi pubblica e privata.

C'è bisogno di una coppia di chiavi pubblica e privata per due attività [task] indipendenti:

  • Firmare gli artefatti di shared state che OpenEmbedded Build System genera con la propria chiave privata.

  • Verificare gli artefatti di stato condivisi con la propria chiave pubblica quando si riutilizzano.

Nota

Per ulteriori informazioni sulla crittografia a chiave pubblica, consultare la pagina di Wikipedia https://en.wikipedia.org/wiki/Public-key_cryptography.

Col tool da riga di comando gpg, genera una nuova coppia di chiavi pubblica e privata:

$ gpg --full-generate-key

Guiderà attraverso i passaggi per la creazione della coppia di chiavi.

Una volta completata la procedura, si dovrebbe essere in grado di visualizzare la nuova chiave con il seguente comando:

$ gpg --list-keys
pub   ed25519 2026-04-17 [SC]
      4049A47E3AAA99D0250966DC5B97632FA7F4E942
uid           [ultimate] Antonin Godard (SState Signing) <antonin.godard\@bootlin.com>
sub   cv25519 2026-04-17 [E]

Nell'esempio precedente, prendere nota dell'identificativo della chiave 4049A47E3AAA99D0250966DC5B97632FA7F4E942. Questo verrà utilizzato per configurare la build.

6.3 Configurazione del Sistema di Build per la Firma degli Artefatti di Shared State

6.3.1 Posizione dello Shared State

Il sistema di build deve essere configurato per firmare i nuovi artefatti di shared state quando vengono generati. La generazione di nuovi artefatti avviene al termine dell'esecuzione di un task.

Per le sezioni seguenti, supponiamo che il sistema di build abbia la directory di shared state (SSTATE_DIR) definita come segue:

SSTATE_DIR = "${TOPDIR}/sstate-cache"

Supponendo che questa directory e la directory temporanea (TMPDIR) siano vuote, eseguiamo il task create_recipe_spdx della ricetta gettext-minimal-native:

$ bitbake gettext-minimal-native -c create_recipe_spdx

Utilizzeremo questo comando come esempio in tutto il documento.

Dopo l'esecuzione, la directory di shared state dovrebbe essere popolata con nuovi file:

$ find $BUILDDIR/sstate-cache/ -name "*gettext-minimal-native*create_recipe_spdx*"
sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst
sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst.siginfo

Questi sono gli artefatti di shared state predefiniti generati da OpenEmbedded Build System. Non sono firmati con GPG per default, quindi vediamo come aggiungere la firma a questi artefatti.

Nota

Nonostante il nome, il file siginfo non è correlato alla firma GPG.

6.3.2 Abilitazione della Firma dello Shared State

Creare un nuovo configuration file sul proprio host in una posizione sicura e aggiungere le due seguenti istruzioni:

SSTATE_VERIFY_SIG = "1"
SSTATE_SIG_KEY = "4049A47E3AAA99D0250966DC5B97632FA7F4E942"
SSTATE_SIG_PASSPHRASE = "<your GPG key passphrase>"

Si consiglia di inserire queste istruzioni in un file separato, poiché contengono informazioni riservate e non devono essere condivise. Per questo esempio, supponiamo che il file si chiami conf/sstate-sig-key.conf.

Ci si può assicurare che questo file sia di proprietà e non leggibile da altri utenti con:

$ chown $USER:$USER conf/sstate-sig-key.conf
$ chmod o-rwx conf/sstate-sig-key.conf

Le istruzioni in questo file definiscono:

  • SSTATE_VERIFY_SIG: impostando questa variabile su "1" si abilita la funzionalità di firma dello shared state.

  • SSTATE_SIG_KEY: l'identificativo della chiave GPG per la firma degli artefatti dello shared state con la chiave privata.

    Nell'esempio, questo corrisponde all'identificativo visualizzato con il comando gpg --list-keys precedente.

  • SSTATE_SIG_PASSPHRASE: la passphrase utilizzata per proteggere la chiave privata, scelta al momento della creazione della coppia di chiavi.

Testiamo la configurazione:

  1. Continuando con l'esempio gettext-minimal-native, rimuoviamo innanzitutto gli artefatti di stato condiviso esistenti, per assicurarci che gli artefatti di shared state per il proprio task do_create_recipe_spdx vengano rigenerati:

    $ rm -r sstate-cache/

  2. Eseguiamo il task create_recipe_spdx per gettext-minimal-native, ma questa volta passiamo il nuovo file sstate-sig-key.conf a BitBake:

    $ bitbake -R conf/sstate-sig-key.conf gettext-minimal-native -c create_recipe_spdx

Elenchiamo nuovamente i file nella directory dello shared state:

$ find sstate-cache/ -name "*gettext-minimal-native*create_recipe_spdx*"
sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst
sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst.sig
sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst.siginfo

È stato creato un nuovo file .sig: questo significa che l'artefatto è stato firmato correttamente e la firma è memorizzata in un file .sig separato.

6.4 Verifica degli Artefatti Firmati dello Shared State

Ora che è stato configurata la build per firmare gli artefatti dello shared state, vediamo come so possono verificare con la corrispondente chiave pubblica della chiave privata.

Nota

La firma dello shared state e la sua verifica possono avvenire su due host diversi, il che significa che un host può occuparsi della firma mentre un altro si limita a verificare gli artefatti. Questa soluzione è preferibile in quanto la chiave privata non dovrebbe essere condivisa tra più host.

Da un configuration file, come ad esempio il file di configurazione del sito, includere le seguenti istruzioni:

SSTATE_VERIFY_SIG = "1"
SSTATE_VALID_SIGS = "5B97632FA7F4E942"

Queste dichiarazioni definiscono:

  • SSTATE_VERIFY_SIG: impostando questa variabile su "1" si abilita la funzionalità di firma dello shared state.

  • SSTATE_VALID_SIGS: un elenco di identificatori di chiave separati da spazi per i quali sono accettati artefatti di shared state.

    Ciò significa che lo stato condiviso verrà riutilizzato solo se è stato firmato con la chiave privata corrispondente all'identificatore di chiave.

    Si noterà qui la forma abbreviata dell'identificativo della chiave, ovvero gli ultimi 16 caratteri dell'identificativo della chiave in forma estesa mostrato con gpg --list-keys (in grassetto qui sotto):

    pub   ed25519 2026-04-17 [SC]
      4049A47E3AAA99D0250966DC5B97632FA7F4E942
uid           [ultimate] Antonin Godard (SState Signing) <antonin.godard@bootlin.com>
sub   cv25519 2026-04-17 [E]

Confermiamo che la verifica della firma funzioni:

  1. Innanzitutto, rimuoviamo gli output temporanei (TMPDIR) dalle build precedenti, in modo che OpenEmbedded Build System ricompili tutto utilizzando lo shared state:

    $ rm -rf tmp/

  2. Quindi, eseguiamo nuovamente il task:

    $ bitbake gettext-minimal-native -c create_recipe_spdx

  3. Per assicurarci che l'artefatto dello shared state sia stato utilizzato correttamente, cerchiamo il task setscene per create_recipe_spdx nell'ultimo file di log di BitBake:

    $ grep create_recipe_spdx_setscene tmp/log/cooker/<machine>/console-latest.log
NOTE: Running setscene task 1 of 1 (../layers/openembedded-core/meta/recipes-core/gettext/gettext-minimal-native_1.0.bb:do_create_recipe_spdx_setscene)
NOTE: recipe gettext-minimal-native-1.0-r0: task do_create_recipe_spdx_setscene: Started
NOTE: recipe gettext-minimal-native-1.0-r0: task do_create_recipe_spdx_setscene: Succeeded

    Lo shared state è stato verificato e utilizzato correttamente!

Nota

Per verificare che la verifica dello shared state funzioni correttamente, è possibile impostare un identificatore di chiave pubblica "fake" in SSTATE_VALID_SIGS:

SSTATE_VALID_SIGS = "CAFECAFECAFECAFE"

Rimuovere nuovamente gli output temporanei:

$ rm -r tmp/

Ora, provare a eseguire il task:

$ bitbake gettext-minimal-native -c create_recipe_spdx

Dovrebbero essere visualizzati dei warning da BitBake sulla console:

WARNING: gettext-minimal-native-1.0-r0 do_create_recipe_spdx_setscene: No accepted signatures found. Good signatures found: 5B97632FA7F4E942.
WARNING: gettext-minimal-native-1.0-r0 do_create_recipe_spdx_setscene: Cannot verify signature on sstate package ../build/sstate-cache/universal/a3/6e/sstate:gettext-minimal-native:x86_64-linux:1.0:r0:x86_64:14:a36ef66df6b8c0cb5a849bc70a99dcfd61e4bacd11cefe6bbaf4978b2b3b617a_create_recipe_spdx.tar.zst, skipping acceleration...
WARNING: gettext-minimal-native-1.0-r0 do_create_recipe_spdx_setscene: No sstate archive obtainable, will run full task instead.
WARNING: Logfile for failed setscene task is ../build/tmp/work/x86_64-linux/gettext-minimal-native/1.0/temp/log.do_create_recipe_spdx_setscene.6994
WARNING: Setscene task (../layers/openembedded-core/meta/recipes-core/gettext/gettext-minimal-native_1.0.bb:do_create_recipe_spdx_setscene) failed with exit code '1' - real task will be run instead

Come si può notare, questo non impedisce a BitBake di proseguire, ma viene eseguito il task reale invece di riutilizzare lo shared state.
