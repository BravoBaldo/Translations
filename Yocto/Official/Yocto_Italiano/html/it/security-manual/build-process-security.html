2 Sicurezza del Processo di Build

OpenEmbedded Build System viene utilizzato per eseguire le compilazioni e la sua progettazione è stata attentamente studiata per garantire sicurezza e riproducibilità. Come qualsiasi sistema, è necessario utilizzarlo con attenzione e in conformità con la sua progettazione affinché ciò sia possibile. Gli utenti del sistema devono tenere presente quanto segue:

  • In generale, ogni input del processo di build viene verificato in qualche modo. Per i file tarball del codice sorgente, viene generato un checksum. Gli alberi di codice sorgente Git hanno una specifica revisione Git. Anche i metadati sono solitamente gestiti tramite controllo di versione e presentano delle revisioni.

    Per ulteriori informazioni, consultare la sezione File Download Support del Manuale Utente di BitBake.

  • Alcuni elementi che possono influenzare la compilazione non vengono verificati. Si presume che il sistema operativo in esecuzione sia sicuro e di versione nota. Il sistema adotta misure significative per isolare l'output da eventuali contaminazioni provenienti dall'host, ma ciò è certamente possibile, soprattutto in modo malevolo.

    Per ulteriori informazioni sulle distribuzioni host supportate, consultare la sezione Distribuzioni Linux Supportate del Manuale di Riferimento di Yocto Project.

  • Le build presuppongono che DL_DIR sia una posizione sicura. Una volta che gli artefatti scaricati entrano in tale posizione, non vengono ri-verificati ripetutamente. Un utente potrebbe modificare gli alberi Git o i file tar presenti in quella posizione in modi che la build potrebbe non rilevare.

  • Le build presuppongono che gli oggetti sstate provenienti da SSTATE_DIR o da un sstate mirror configurato siano sicuri (con signature checks se configurati).

  • Lo strumento di build principale, BitBake, è un motore di esecuzione ed esegue codice sia durante la compilazione che durante l'analisi delle ricette. Questo non rappresenta un problema di sicurezza, bensì una parte essenziale della sua funzione e del suo scopo.

  • OpenEmbedded-Core (OE-Core) è stato ampiamente testato per la riproducibilità dei problemi, ma altri layer, le relative ricette e il codice potrebbero non essere stati testati altrettanto a fondo. Tali test di riproducibilità sono a disposizione di chiunque desideri eseguirli sui propri layer e sul proprio codice.

  • Le build combinano molti componenti software diversi e ci si basa sul presupposto che non vi siano problemi nelle relative codebase. Raccomandiamo di configurare gli ambienti di compilazione in modo tale che, qualora venisse scoperto un problema di questo tipo (cosa che potrebbe accadere in futuro), gli ambienti stessi possano essere semplicemente eliminati e ricostruiti da zero, ovvero siano "usa e getta".
