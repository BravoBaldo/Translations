1 Identificazione del Componente

L'ecosistema Yocto Project e OpenEmbedded è costituito da layer, quindi il primo passo è identificare il componente in cui è più probabile che risieda il problema. Ad esempio, se si riscontra un problema hardware, è probabile che sia correlato al BSP in uso e il posto migliore a cui rivolgersi per chiedere consiglio è il fornitore del BSP o il layer. Se il problema riguarda la compilazione/configurazione e si utilizza una distribuzione, quest'ultima sarà probabilmente il primo punto di riferimento. Se il problema è generico e/o riguarda le classi principali o i metadati, il componente appropriato potrebbe essere il core layer o BitBake.

Ogni layer di metadati utilizzato dovrebbe contenere un file README che spiega dove segnalare i problemi, dove inviare le modifiche e come contattare i manutentori.

Se il problema si trova nel livello dei metadati principali (OpenEmbedded-Core) o in BitBake, è possibile segnalarlo nel Yocto Project Bugzilla. La mailing list yocto è un punto di riferimento generico dove è possibile inviare domande se non si riesce a capire dove indirizzarle.
